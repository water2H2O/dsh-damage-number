# dsh-damage-number

给 [dsh-whale-widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget) 小鲸鱼挂件加一层「**伤害数字**」：
消耗落进你设定的区间时，在**鲸鱼头顶**弹出一个红色数字，向上飘起并淡出；区间内按概率随机，**达到区间上限必定弹出**。

就是「花了几分钱，鲸鱼头上跳一下红字」的那个手感 —— 多数时候随机、偶尔必中。

```
        -¥0.03        ← 弹出 → 过冲放大 → 缓慢上浮 → 淡出
          🐋
```

- 🔁 **两种模式**：`每轮结束时跳一次`（按区间概率）/ `工作中每隔一段时间跳`（对话进行期间持续输出，**数字是本轮到目前为止的真实花费**，逐条累加不估算）。
- ⚡ **即时**：宿主在 `turn/end` 的同一刻用 SSE 叫醒页面，延迟约一次本机往返（几毫秒），不是「最多等一秒」。
- 🐢 **看得清**：默认动画 1800ms，其中超过 65% 的时间完全不透明地缓慢上浮 —— 不再是「一闪而过」。
- ↔️ **每次跳都有轻微横向偏移**（按 **%** 可调），多次飘字不会叠在同一个点上。
- 🎛️ **极简设置**：入口在小鲸鱼的「提示与音效设置」面板里，**只有 6 个数字框 + 1 个下拉**（模式 / 区间 / 概率 / 间隔 / 时长 / 偏移）。颜色、描边、前缀这些不常动的项从界面里拿掉，改 `~/.dsh/.dshdmg.json` 即可，而且不会被「保存」冲掉。
- 🧪 **不花钱就能试**：面板里有「预览」按钮，或按当前区间掷上千次骰子验证概率。

## 前置

需要先装好 **`dsh-whale-widget`**（本插件从它的 `/dsh-whale/last-turn.json` 读每轮金额）。
挂件没装时本插件不会报错，只是安静地什么都不做。

## 安装

### 桌面端（Electron 客户端）

桌面端读的是 `desktop` profile，而 `dsh plugin` 命令行**按设计拒绝**碰它
（`error: profile "desktop" is managed exclusively by the Electron application`）。
所以先在任意位置克隆本仓库，再**在桌面端的会话里让 DSH 自己装**：

```powershell
git clone https://github.com/water2H2O/dsh-damage-number.git D:\Plugins\dsh-damage-number
```

> 把 `dsh-damage-number` 装上，源目录是 `D:\Plugins\dsh-damage-number`

（它会调用内置 `plugin_manager`，在本 profile 里用自带 pnpm 完成 `link:` 安装并写进 `dsh.profile.bundles`。）

⚠️ 克隆到的目录**之后不能移动或重命名** —— `link:` 安装是指向该目录的软链，移动后要重新 add 一次。

### 普通 `dsh web`

```powershell
git clone https://github.com/water2H2O/dsh-damage-number.git
dsh plugin --profile web add link:<克隆到的绝对路径>
```

也可以直接按 Git 源安装（pnpm 会自己拉取）：

```powershell
dsh plugin --profile web add github:water2H2O/dsh-damage-number
```

> `link:` 是软链安装：源目录里的文件改了立即生效；**装完不能移动/重命名该目录**。
> 想改成拷贝安装用 `file:<绝对路径>`（此后源目录改动不同步，需重新 add）。
> 升级 `dsh-whale-widget` 不会影响本插件 —— 两者没有代码耦合，只通过 HTTP 接口通信。

## 生效方式（两个半区，规则不一样）

| 你改了什么 | 怎么生效 |
|---|---|
| `assets/overlay.js`、`assets/panel.js`（浏览器半区） | 宿主按 mtime 热读取 → **硬刷新页面（Ctrl+F5）** |
| `lib/index.js`（宿主半区） | **需要重启客户端**（或重启 `dsh web`） |

> ⚠️ 宿主半区**不能**靠插件管理器的「禁用 → 启用」来热重载。
> 实测：node 的 ESM 按 URL 缓存模块，禁用/启用只是重跑 `apply()`，拿到的仍是缓存里的旧实现 ——
> 新路由依然 404。所以改了 `lib/` 就老老实实重启一次。
> （曾经试过用「薄壳 + 带时间戳的动态 import」绕开缓存，也无效：连入口文件本身都在缓存里。）

> 💡 **浏览器半区比宿主半区新会怎样**：宿主只认识自己那份键表（`sanitize()`），遇到不认识的键会**静默丢掉**，
> 表现就是"点了保存、卡片关了、设置却没变"。所以保存时会把你发出去的每个键跟回来的值逐个比对，
> 对不上就**明确报错**并点名是哪些键（会提示重启客户端），不会让你以为是权限问题。

注入行走的是 `webserver/index-inject` 结构化行（桌面端唯一通道）+ `tapIndex`（web 形态），两条并存、各自去重。
新装后页面里没反应，先刷新页面；仍无反应再重开客户端（桌面端存在"新装需要重开一次"的已知现象）。

## 即时触发（为什么它能"立刻"跳）

金额的唯一真相始终在小鲸鱼挂件里 —— 它监听 `session/event`，收到 `turn/end` 时**立即**结算本轮
（含峰谷定价与缓存命中折算）并刷新自身的 `/dsh-whale/last-turn.json`。所以慢的从来不是数据源，
而是"浏览器隔一秒去问一次"。

本插件的宿主半区订阅**同一个** `session/event`，在 `turn/end` 的同一刻通过 SSE 广播一帧；
页面收到就立刻去取一次数。金额口径没有任何复制，宿主只负责"叫醒"：

```
turn/end ──► 挂件结算 lastTurn(同刻)
          └► 宿主广播 SSE ──► 页面立刻 fetch last-turn.json ──► 判定 ──► 飘字
                                        延迟 ≈ 一次本机往返(几毫秒)
```

两条通道谁先到算谁，并且**都能独立工作**：

| 通道 | 默认 | 作用 |
|---|---|---|
| ① 宿主 SSE `/dsh-dmg/events` | 开（`pushEnabled`） | 主通道，延迟几毫秒；同时携带 `activity` 帧（开始/结束工作） |
| ② 兜底轮询 | 2000ms（`pollMs`） | SSE 断开/不可用/被关掉时顶上来 |
| ③ 活动轮询 `/dsh-dmg/activity.json` | 3 秒（仅持续模式） | 持续模式"在不在干活"的**可信来源**；不开持续模式就一个请求都不发 |

- SSE **重连成功（`onopen`）时也会立刻取一次** —— 断线期间结束的那一轮由此补上，不用等下一次轮询。
- 面板里会实时显示 `推送:已连接 / 重连中 / 已关闭`，持续模式下还会显示 `工作中:是/否`、
  `间隔 Ns`、`本轮进行中金额`，以及兜底轮询间隔和本次已触发次数。

## 设置面板

**位置**：右键鲸鱼（或点 ☰）→ **音效与提示** → **全局设置** → 面板底部多了一行 **「受击提示设置」**，点它打开。

入口行本身就是**总开关**（左边那个 `[✓]`），和鲸鱼原有四个入口行一样立即生效；右侧摘要实时显示
`区间 · 概率`（例如 `1 分–10 分 · 25%→100%`，关掉则显示 `已关闭`）。

面板里**只有这些**（刻意做窄：能做到"看一眼就知道能调什么"）：

```
受击提示设置
[✓] 启用受击提示
模式  [每轮结束时跳一次 ▾]
区间  [1] 分 ～ [10] 分
下限概率 [25] %   →   上限处 100%
间隔  [5] 秒
每轮结束时按区间概率跳一次:到上限必定跳;上下限填一样 = 纯阈值。
显示时长 [1800] ms   横向偏移 [18] %
[预览一下]
[取消] [恢复默认] [保存]
```

一共 **6 个数字框 + 1 个下拉 + 4 个按钮**。`间隔` 只在 `工作中每隔一段时间跳` 模式下可用（另一个模式下是灰的），
说明文字也会跟着模式切换。

底部是 `取消 / 恢复默认 / 保存`。**保存会立刻 PUT 到宿主并即刻生效**（宿主那边是原子替换写入）。
`恢复默认` 只改界面上的值，仍要点「保存」才落盘。

### 其余设置请改配置文件

为了界面清爽，下面这些**从界面里拿掉了**，但它们仍然有效 —— 直接改
`$DSH_HOME/.dshdmg.json`（见下文「配置」），改完最迟 30 秒生效、刷新页面立即生效：

| 想改什么 | 键 |
|---|---|
| 数字颜色 / 字号 | `color`、`fontSizePx` |
| 描边粗细 / 颜色 | `strokeWidth`、`strokeColor` |
| 金额前缀 / 小数位 | `prefix`、`decimals` |
| 上浮距离 / 同屏上限 | `risePx`、`maxStack` |
| 落点位置（头顶偏左偏右、偏高偏低） | `headOffsetX`、`headOffsetY` |
| 推送 / 轮询通道 | `pushEnabled`、`pollMs` |
| 只对主会话生效 | `mainSessionOnly` |

> **拿掉界面控件 ≠ 把这些配置项清成默认值**。面板只提交它自己那几个键，
> 保存时用现有配置做底再合并 —— 所以你手改过的 `color`、`maxStack` 之类不会被一次「保存」冲掉
> （测试台里专门钉了这条）。

> 单位说明：界面上区间按**分**填、概率与偏移按 **%** 填（"消耗几分钱"才是人话），
> 配置文件里存的仍是最初的口径（元 / 0~1 的比例）。换算由面板负责，你不需要手算 `0.01`。

### 不花钱地试

- **预览一下**：就地飘一个数字（取区间中点），只看外观和落点，**不走判定、不发任何写请求**（测试台里断言了这一点）。
- **控制台**（界面里没有的功能都在这里，一样不花钱）：
  - `__dshDmgNumber.preview(0.05)` —— 指定金额飘一个
  - `__dshDmgNumber.burstTick()` —— 立刻手动来一次「工作中的间隔跳动」
  - `__dshDmgNumber.simulate(0.055, 2000)` —— 按当前区间掷 2000 次，返回 `{ hits, rate, expected }`；
    例如区间 `1–10 分`、下限概率 25%、金额 `0.055`，实测应当 ≈ 62.5%
  - `__dshDmgNumber.getRuntime()` —— 模式、`working`、间隔、**本轮进行中金额**、触发次数、同屏数量
  - `__dshDmgNumber.setConfig({ color: '#ff8800' })` —— 临时改（刷新即失效；要持久就用面板或改配置文件）

## 两种跳动模式

| 模式 | 什么时候跳 | 跳的数字 |
|---|---|---|
| `每轮结束时跳一次`（默认） | 每轮对话结束时，按下面的区间概率判定 | 该轮的**真实**金额 |
| `工作中每隔一段时间跳` | 对话进行期间每 `tickSec` 秒**无条件**跳一次；每轮结束那一次仍按区间概率判定 | **本轮到目前为止的真实花费**（逐条累加，越跳越大） |

```
每轮结束时：  ────────────────► ●                 (一轮结束, 按概率跳)
工作中每隔：  ──●───●───●───●───► ●               (每 N 秒一跳 + 结束结算)
                0.01  0.03  0.05  0.06   0.062    (数字一路上涨)
```

### 持续模式的数字是怎么来的

**不是估算，也不是重复上一轮** —— 而是把挂件自己那份账**实时算了一遍**。

小鲸鱼确实没有暴露"本轮进行中的金额"（它的 `turnAggs` 只在内存里，`turn/end` 才结算落盘），
但它算钱用的三样东西我们都能拿到：

| 需要什么 | 从哪来 |
|---|---|
| 每条消息的 token 用量 | `session/event` 的 `assistant/message`，带 `usage`（input / cacheRead / output）—— **和挂件监听的是同一个事件流** |
| 价目表 | 挂件源码 `lib/index.js` 里的常量（`PRICING` / `BASE_PRICE` / `PRO_PRICE`） |
| 峰谷规则 | 同上（`isPeakTime()`：工作日 9–12、14–18 北京时间为高峰；周末与法定节假日全天谷价） |
| 计费公式 | 同上，`lib/index.js:899`，逐字照抄 |

```
cost = (cache/1e6)*hit[峰?1:0] + (input/1e6)*miss[峰?1:0] + (output/1e6)*out[峰?1:0]
```

所以宿主每收到一条 `assistant/message` 就把这一条的钱加上去，随 `activity.json` 下发给前端 ——
前端跳的就是这个数。**每轮结束那一次仍然用挂件给的结算金额**，所以"最终数字"永远是权威值。

`tickAmount` 决定每跳报哪个数（配置文件里改，界面上没有）：

| 值 | 每跳的数字 | 观感 |
|---|---|---|
| `turnTotal`（默认） | 本轮累计花费 | 数字递增，像血量一直在掉 |
| `intervalDelta` | 距上次跳动这段时间**新增**的花费 | 像持续掉血的小数字；这段时间没花钱就**不跳** |

关于持续模式的三个要点：

- **有一层自检防"悄悄算错"**：镜像的价目表和峰谷规则是**照抄**来的，官方一调价它就会变旧。
  所以每轮结算时都会拿"我算的本轮累计"和"挂件给的真实金额"比一次，**差超过 5% 就在控制台点名警告**
  （告诉你该更新 `lib/index.js` 里的 `DMG_PRICING`）。`status.json` 里还有一份峰谷自检探针可随时核对。
- **间隔跳不做概率判定**。"只要在干活就一直输出"是它的本意；概率那一层留给每轮结束那一次，
  所以「区间 / 概率」这些设置在任何模式下都有意义。
- **判断"在不在干活"用的是真实状态**：宿主监听 `session/event`（`turn/start`、`step/start`、
  `assistant/message`、`tool/call` 都会点亮"在干活"，`turn/end` 与 `session/disposed` 负责收尾），
  前端每 3 秒取一次 `/dsh-dmg/activity.json`；SSE 的 `activity` 帧只是让它反应更快，不是可信来源。

## 触发规则

设区间 `[minAmount, maxAmount]`（**每轮结束那一次**按这张表判定）：

| 本轮消耗 | 行为 |
|---|---|
| `amount < minAmount` | 不跳 |
| `minAmount ≤ amount < maxAmount` | 以概率 `minProbability + (1 - minProbability) × 区间内进度` 跳 |
| `amount ≥ maxAmount` | **必定跳** |
| `minAmount == maxAmount` | 退化成纯阈值：达到即必跳 |

默认 `minAmount = 0.01`、`maxAmount = 0.10`、`minProbability = 0.25`：

| 消耗 | 触发概率 |
|---|---|
| ¥0.010（1 分） | 25% |
| ¥0.0325 | 43.75% |
| ¥0.055（5.5 分） | 62.5% |
| ¥0.0775 | 81.25% |
| ≥ ¥0.10（10 分） | 100% |

### 「一轮」是怎么算的（子代理）

挂件的 `lastTurn` 对**任意会话**的 `turn/end` 都会刷新 —— **子代理会话也算**。
所以一轮对话里如果派了子代理，`seq` 可能涨好几次，伤害数字也可能跳不止一次。

勾上面板里的 **「只对主会话结算」**（`mainSessionOnly`）后，子代理的 `turn/end` 不再**即时**触发；
但要注意：这条只作用于 SSE 那条快通道，**推送不可用而退回轮询时仍可能被兜底取到**。
想要完全精确，只能改挂件侧的语义（本插件看不到 `last-turn.json` 属于哪个会话）。

### 轮次对齐（刷新页面不漏）

触发靠 `last-turn.json` 的 `seq`，并把"已结算到哪个 seq"持久化在
`localStorage` 的 `dshw-dmg-last-seq`（与小鲸鱼自己的 `dshw-last-seq` 分开）：

- **本机第一次运行**：只立基准，绝不把账本里的历史轮次当成"刚刚花的钱"补弹一遍。
- **刷新页面 / 重开客户端**：在页面不在时结束的那一轮会被补上（启动轮就判定），不会漏。
- **seq 落后于记忆**（挂件重启、`.dshw-turn.json` 丢失）：只拉齐基准，不飘字 —— 避免用陈旧基准乱跳。
- 浏览器禁用了 `localStorage`（隐私模式）：退化成"本次会话内对齐"，功能不报错。

## 配置

配置文件：`$DSH_HOME/.dshdmg.json`（默认 `~/.dsh/.dshdmg.json`），**不存在也能跑**（用默认值）。
用面板改最省事；手改也行，改完最迟 30 秒生效，刷新页面立即生效。

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关（= 入口行那个 `[✓]`） |
| `mode` | `"turnEnd"` | `turnEnd` = 只在每轮结束时跳；`working` = 工作中按 `tickSec` 持续跳 |
| `tickSec` | `5` | 持续模式的间隔秒数（夹取到 0.5~3600） |
| `tickAmount` | `"turnTotal"` | 持续模式每跳报什么：`turnTotal` = 本轮累计；`intervalDelta` = 距上次跳动新增的花费 |
| `minAmount` | `0.01` | 伤害区间下限（**元**）：低于它必不跳 |
| `maxAmount` | `0.1` | 伤害区间上限（**元**）：达到/超过必跳 |
| `minProbability` | `0.25` | 刚好到下限时的触发概率（0~1） |
| `pushEnabled` | `true` | 用宿主 SSE 即时叫醒；关掉则退回纯轮询 |
| `mainSessionOnly` | `false` | 只对主会话生效（`turn` 帧与"工作中"判定都按它过滤） |
| `pollMs` | `2000` | 兜底轮询间隔（夹取到 250~60000） |
| `prefix` | `"-¥"` | 金额前缀 |
| `decimals` | `2` | 小数位；2 位会把"小于半分钱"显示成 0.00 时自动补到 3 位 |
| `color` | `"#ff3b30"` | 数字颜色 |
| `strokeColor` | `"#ffffff"` | 描边颜色（保证在任何背景上都看得清） |
| `strokeWidth` | `3` | 描边宽度（px），设 0 关闭描边 |
| `fontSizePx` | `30` | 字号（px） |
| `risePx` | `96` | 上浮距离（px） |
| `riseMs` | `1800` | 动画总时长（ms）。关键帧里 0.28→0.78 是缓慢上浮的主可见段，所以**调大它 = 飘得更慢 + 看得更久** |
| `headOffsetX` | `0.5` | 落点横向位置（相对鲸鱼精灵图宽度的比例，0.5 = 居中） |
| `headOffsetY` | `0.12` | 落点纵向位置（相对鲸鱼精灵图高度的比例，0.12 ≈ 头顶） |
| `jitterX` | `0.18` | 每次跳动的横向随机偏移幅度（相对鲸鱼宽度，0~1）。面板里按 **%** 呈现（默认 18%） |
| `maxStack` | `6` | 同屏最多几个飘字（超了丢最旧的） |

> 面板只暴露了其中一部分（基础项 + 高级折叠区）；没暴露的键直接改这个文件即可，一样生效。

读配置：`GET /dsh-dmg/config.json`；改配置：`PUT /dsh-dmg/config.json`（**仅限本机回环**，非回环一律 403）。

## 自查

```powershell
# 插件状态:版本、配置落点、数据源、信任栅栏、SSE 连接数、活动状态与最近一次 turn/end
curl http://127.0.0.1:<端口>/dsh-dmg/status.json
# "现在有没有在干活"(持续模式的状态源)
curl http://127.0.0.1:<端口>/dsh-dmg/activity.json
# 当前配置 / 浏览器半区脚本 / 设置面板脚本
curl http://127.0.0.1:<端口>/dsh-dmg/config.json
curl http://127.0.0.1:<端口>/dsh-dmg/overlay.js
curl http://127.0.0.1:<端口>/dsh-dmg/panel.js
```

> 端口：`dsh web` 默认 `3080`；官方桌面端是动态端口 —— 在会话里读环境变量 `DSH_WEB_URL` 即可（例如
> `http://127.0.0.1:19387`）。

> 这些路由都接了 DSH 的浏览器信任栅栏，所以**不带会话凭据的裸 curl 会返回 401**，
> 伪造 Host / 跨站标记是 403 —— 返回 401/403 就说明路由已注册、栅栏在工作，不是接口坏了。
> 想区分"路由已注册"和"没注册"：**没注册的路径返回 404**（会落到 SPA 兜底）。

`status.json` 里几个值得看的字段：

- `sseClients`：**> 0 说明至少有一个页面真的把 SSE 挂上了**；一直是 0 就说明推送没建立（会退回轮询）。
- `activity`：`{ working, mainWorking, since, sessions }` —— 持续模式就是靠它判断"在不在干活"。
- `lastTurnEnd`：最近一次 `turn/end` 的时间、会话、是否子代理 —— 用来确认宿主确实收到了事件。

浏览器控制台里可以直接调：

```js
__dshDmgNumber.preview(0.05)          // 立刻手动飘一个 ¥0.05(不判定、不写配置)
__dshDmgNumber.burstTick()            // 立刻手动来一次「工作中的间隔跳动」
__dshDmgNumber.simulate(0.055, 2000)  // 掷 2000 次,返回 { hits, rate, expected }
__dshDmgNumber.roll(0.05)             // 单次判定结果 { hit, p, roll, reason }
__dshDmgNumber.syncActivity()         // 立刻刷新一次"是否在干活"
__dshDmgNumber.getRuntime()           // SSE 状态、模式、working、间隔、本轮进行中金额、触发次数
__dshDmgNumber.openPanel()            // 打开设置面板(小鲸鱼面板找不到时的兜底入口)
__dshDmgNumber.getConfig() / setConfig({ mode: 'working', tickSec: 3 })
```

  「预览」不发任何请求、勾选框即时保存、

> 这样"页面卡死"就从"只能靠人手点出来"变成了可断言的失败。

## 已知限制

- **入口行依赖小鲸鱼的面板 DOM**（`.dshwv-bubmask` / `.dshwv-bubcard` / `.dshwv-bubtitle` 与标题文字
  `提示与音效`）。鲸鱼大改面板会让这一行消失 —— 但**功能不会坏**：
  控制台里 `__dshDmgNumber.openPanel()` 永远能打开设置面板。
  之所以不直接改鲸鱼源码：它在 `node_modules` 里，鲸鱼一升级就被整包覆盖，改动会静默消失。
- **子代理轮次**：见上文「'一轮'是怎么算的」。
- **SSE 长连接可能被服务器/中间层断开**：`EventSource` 会自动重连，且重连成功时会立刻补取一次，
  所以最多是短暂退回轮询，不会丢轮次。
- **保存需要本机访问**：写配置只接受回环地址来源。从局域网 / 反向代理地址打开页面时，读没问题，
  点保存会被拒（面板会明确提示失败原因，不会静默吞掉）。
- **镜像计价可能变旧**：持续模式跳的数字是按挂件源码里的价目表/峰谷规则**照抄**算的。
  官方调价或挂件改规则后，抄来的那份就会偏 —— 所以每轮结算会自动对比一次并在控制台警告（差 >5%）。
  结算数字永远取自挂件，是准的。自定义 API 模型的单价存在挂件内存里、读不到，这类模型按内置
  `_default`（Flash 价）估 —— 同样会被上面那条自检逮到。
- **宿主半区与浏览器半区的版本可能不同步**（浏览器半区是热读取的，宿主半区要重启）。
  这种情况下保存会被宿主丢掉不认识的键 —— 面板会明确报错并点名，不会静默。

## 设计取舍

- **不碰小鲸鱼的 `node_modules`**：本插件独立安装，升级挂件不会被覆盖。
- **不解析会话日志、不复制定价**：金额直接取挂件算好的 `/dsh-whale/last-turn.json`，
  含它的峰谷定价与缓存命中折算；宿主订阅 `session/event` 只用来"叫醒"，不参与算钱。
- **落点量的是精灵图**（`.dshwv-root .dshwv-img`），不是挂件根节点 —— 根节点是方块，
  精灵图只占右下 59.45%，量错了数字会飘在鲸鱼左上方的空气里。拖动鲸鱼后落点自动跟随。
- **关键帧只用 px**：外层负责定位、内层负责动画，避免 `%` 与 `calc()` 混插时插值不可靠。
- **配置读失败不重置**：一次 404/断连不会把你调好的区间静默冲回默认值。
- **轮次基准持久化**：刷新页面不会漏掉刚结束的那一轮，小鲸鱼挂件自己也是这个策略。
- **⛔ MutationObserver 的回调里绝不写"没变化的 DOM"**（改这个插件前请务必读这条）。
  真实 DOM 里 `el.textContent = x` 就算 x 与当前内容**完全相同**，也会把原文本节点删掉再插一个新的
  —— 它永远是一次 childList 变更。而我们的 observer 回调里会刷新入口行摘要，于是：

  ```
  回调 → 写 DOM → MutationObserver 再派发 → 回调 → …    ← 微任务队列永远排不空
  ```

  v0.2.0 首次发布时就是踩了这个坑：**点开小鲸鱼的「全局设置」会把整个 harness 卡死**
  （入口行第一次被注入、循环被点燃）。现在有三道闸门同时防它：
  ① 写入端 `setText`/`setChecked` 先比较再写；② 回调只对"鲸鱼面板出现/消失"这类变更作出反应；
  ③ 扫描合并到下一次 `rAF`。任何一处被"简化"掉都可能让风暴回来 —— `paneltest.mjs` 第 14 节专门钉这个。
- **面板遮罩复用鲸鱼的类名**：鲸鱼的全局 `pointerdown` 处理器见到 `.dshwv-bubmask` 会直接 return
  （"面板内部交给面板自己处理"），所以它不会来干涉我们的卡片；卡片本体再用它公开的
  `window.dshwRegisterMask(el)` 登记层级。
- **信任栅栏与挂件同款语义**：宿主栅栏可用时，非回环 Host 交给它判（它才知道 `--trusted-host` 声明了谁）；
  栅栏自己抛异常则 fail-closed 按拒绝处理。这五种情形都写进了测试。
